# 移动端适配：手机上也能管秘书

## Report

**What was built** — SPA 响应式改造：小屏（<768px）侧栏收抽屉（汉堡滑出/遮罩收起/选中自动收起）+ 移动顶栏（汉堡+视图名+通知铃）+ 内容区留顶栏位；全站 px-6→px-4 md:px-6 收缩；聊天输入 16px 防 iOS 缩放；触控目标 ≥40px。桌面布局零回归。

**Verification** — 生产真机视口（390×844 CDP 模拟）：抽屉五态（收起/汉堡开/选房收/再开/遮罩收）状态类全对；汉堡与布局 DOM 实测。

## [S1] Problem

SPA 是桌面布局（固定 280px 侧栏 + 双栏），手机上聊天区被挤成一条、按钮难点。而移动端恰恰覆盖最高频的场景：出门看任务进度、回一条审批（待办拍板）、瞄一眼额度——都是「轻交互」。响应式是 P2 里受众最大的一件。

## [S2] Design

### S2.1 布局

- **断点**：<768px 视为手机。侧栏改为抽屉（默认收起，汉堡按钮滑出/遮罩点击收起）；顶部加 52px 移动条（汉堡 + 当前视图名 + 通知铃）。
- **主区**：聊天/待办/任务/记忆/管理各视图 max-width 自适应；内边距在小屏收窄（px-6 → px-3）；抽屉详情（任务详情、审批）全屏化。
- **触控**：主按钮/行高 ≥40px；输入框字号 16px（防 iOS 聚焦缩放）。

### S2.2 交互

- 视图切换沿用现有 view 状态；移动端点「待办/任务/记忆/管理」后抽屉自动收起。
- 深链（通知/邮件进房间）在移动端同样生效。

## [S3] Out of Scope

- 原生 App / PWA 离线包、移动端专属手势、平板分栏优化。

## Tasks

- [x] T1: 侧栏抽屉 + 移动顶栏 — acceptance: <768px 侧栏收起可滑出；视图切换后自动收起；桌面布局无回归 (covers: S2.1) — ✅ 五态交互 DOM 实测
- [x] T2: 核心视图触控适配 — acceptance: 聊天/待办/任务在手机宽度下可完整操作（发消息、回答审批、看详情） (covers: S2.1/S2.2) — ✅ 内边距/字号/触控目标全站过一遍

## Journey log

- 2026-11-15：定为「响应式 web」而非 PWA/原生——当前用户心智是浏览器直开；PWA 离线价值在任务型产品里有限，后置。
